**已判定为「有意取舍」，不改**
- R3-B3：检查点不消费，会话被钉在旧消息 → 这正是需求 5「进群默认在检查点」；逃生口（清除入口）已由 B1 修复打通。
- R3-B4：默认开启后所有右键延迟 500ms → 用户明确选择「默认开」，并提供 JSON 开关 `saveCheckpointOnDoubleRightClick`。
- R1-P0-3：`Flag::NoForwards` 成为死位、4 个读点恒 false → 即需求 2/3/4 的预期解锁效果。
- R1-P0-2：`data_chat.h:27` `AyuNoForwards = (1 << 31)` 符号位 UB → 改枚举底层类型会牵动不可见的 `base::flags`（`Telegram/lib_base` 未初始化），风险大于收益，**留作技术债**。

**未修（已知缺口）**
- 设置页无该开关的 UI 复选框（`ayu.addChooseButton` 是枚举型，bool 行需未验证的 API）→ 可手改 `tdata/ayu_settings.json`。
- peer 菜单跳转不携带 topic（`showPeerHistory` 无 topic 参数）→ 话题检查点跳转可能落在群主页。
- 账号注销/删历史不清理孤儿检查点行。
- 本机无法编译（37/37 子模块未初始化 + 无 cmake/docker），**所有结论均为静态核验**。

## 4. 需求 7（Edit & Resend / 重放）状态：**未实现**，附阻塞分析
ADR-0003 有完整方案，但落地需要「从消息右键菜单写入主输入框」的公开路径。逐层取证结果：
- `HistoryWidget::insertTextAtCursor(const QString&)` 是 public（`history/history_widget.h:113`），但**从菜单侧拿不到 HistoryWidget**：`History::owner()` 继承自 `PeerData::owner()`（`data/data_peer.h:226`）返回 `Data::Session&`，不是 widget；`MainWidget` 也不暴露 history widget（`mainwidget.h` 全文仅前向声明 + 私有成员 `_history`）；`Window::ActiveInstance()` 所在头不在本树（`window/window.h` 未找到）。
- 备选路线「写本地草稿 + 切到聊天」需要 `Data::Draft(const TextWithTags&, ...)`（`data/data_drafts.h:59`）与 `TextWithEntities → TextWithTags` 转换，`TextWithTags`/`Ui::InputField` 都在未初始化的 `Telegram/lib_ui` 子模块里，无法核对签名。
- 结论：在本 checkout（37/37 子模块未初始化、零编译能力）里**任何实现都是盲写**，与本仓库的证据纪律冲突，故不落代码。
可选路径（按成本排序）：① 在外部构建机上实现（有编译器兜底）；② 初始化 `Telegram/lib_ui` 子模块后由主线程实现；③ 零新代码的近似方案：现有「重复消息」已能产生一份副本，用户双击**自己发出的副本**即可进入原生编辑窗（即 Firefox 式「可编辑重发」的手工路径）。
